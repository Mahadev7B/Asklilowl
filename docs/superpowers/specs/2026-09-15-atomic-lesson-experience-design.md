# Atomic AskLilOwl Lesson Experience

## Goal

When a learner asks a plain educational question, AskLilOwl presents one complete lesson card or a single retry message. It must never reveal a partial lesson with missing visuals, a missing quiz, or an unavailable narration track.

## User experience

1. The learner asks only a question, such as “How is glass made?”
2. The active ChatGPT model researches when appropriate and supplies the lesson text, quiz, and one concise visual prompt for each slide. It must not ask the learner to request a quiz, audience level, images, or narration.
3. The AskLilOwl server creates all slide illustrations and one whole-lesson Nova narration track before it returns the widget result.
4. The widget preloads every server-managed image and reveals the lesson only after every required asset is usable.
5. If any required generation, asset fetch, or validation fails, the widget displays only: “Lesson not available right now. Sorry—please try again.”
6. The learner taps Start to begin sound because browsers may block unprompted playback. Start must play the already-prepared single track; it must not make another TTS request.

## Architecture

The existing `create_lesson` tool remains the single ChatGPT integration point. Its input changes from host-managed `images` file objects to a required `imagePrompt` on every teaching slide. The server uses the OpenAI Image API for one focused illustration per slide and uses the existing OpenAI Speech API service once for the combined visible slide text.

Generated bytes are held in a bounded, short-lived server asset store. Signed URLs identify opaque asset IDs; neither source images, lesson text, nor API credentials appear in a URL. The HTTP server serves those assets from `/api/assets/:token` with no-store caching and validates the token before returning bytes. A restarted server or expired token is treated as a lesson-unavailable outcome rather than displaying a partial lesson.

The server does not call native ChatGPT image generation, so ChatGPT does not need to present a separate image gallery. It asks ChatGPT only for a clear visual prompt per slide. The default image model and quality are environment-configured, with a quality-oriented default selected after a live test.

## Interfaces

- `slide.imagePrompt: string` is required, has a 1,000 character cap, and describes one uncluttered educational visual.
- `createLessonAssetService()` produces `prepare({ slidePrompts, narration })` and returns an image for every slide plus one audio URL, or throws. It does not return partial results.
- `buildLesson(args, { images, audioUrl, voice })` requires exactly one normalized image per slide and maps slide `n` to image `n`.
- The widget accepts only a lesson whose image count equals slide count, every slide has a valid image index, a non-empty quiz, and an available audio URL. It preloads all image URLs before unhiding `#lesson`.

## Error handling

- Invalid lesson shapes are rejected before any API request.
- A failed image or audio generation fails the tool result without returning structured lesson content.
- An expired or inaccessible asset URL makes the widget show the generic retry state.
- No retry loop silently creates additional paid image or TTS calls.
- Automated tests use fake services only. A real API call occurs only in a user-visible live test after deployment.

## Global constraints

- One TTS request per lesson; no per-slide TTS.
- One generated illustration per teaching slide; no reuse, dense poster, collage, or unvalidated image.
- Server-side API keys only; do not expose key values, prompts with private user data, or raw provider responses.
- Use official OpenAI Image API generation calls and preserve current safety/guardrail behavior.
- Retain the existing mobile-first widget and quiz interaction.
