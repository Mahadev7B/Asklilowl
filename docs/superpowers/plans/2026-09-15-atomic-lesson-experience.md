# Atomic AskLilOwl Lesson Experience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver one complete, validated AskLilOwl lesson card with server-managed images and prepared single-track narration, or a single retry state.

**Architecture:** ChatGPT supplies lesson text, quiz, and one visual prompt per slide. A server asset service generates all visuals and the single Nova audio track before `create_lesson` returns. A signed, bounded asset cache serves those bytes to the widget. The widget preloads every required asset before revealing the lesson.

**Tech Stack:** Node.js 20, MCP Apps SDK, Zod, native `fetch`, OpenAI Image API, OpenAI Speech API, jsdom, Node test runner.

**Spec:** `docs/superpowers/specs/2026-09-15-atomic-lesson-experience-design.md`

## Global Constraints

- Use one Image API generation per teaching slide and one Speech API generation per lesson.
- Reject any lesson without exactly one valid image per slide, a non-empty quiz, and prepared narration.
- Do not make real API calls in automated tests.
- Keep generated bytes server-side behind short-lived signed URLs; do not store credentials or raw bytes in MCP results.
- If any asset fails, return no partial lesson.
